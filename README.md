# OpenDenshaGO 0.1.6

## 本版操作

### 速限判定
- 同方向連續彎道採整組最低限速，從第一段彎道入口開始生效。例如同一彎道組入口 209 m 為 35 km/h、238 m 降至 25 km/h，改為從 209 m 起採 25 km/h。
- OSM 圓弧間若夾著小於目前全車長的短直線，且前後彎向相同，視為同一組的連接段；反向彎道或至少一個車長的直線會分組。
- 提速點到下一個降速點不足目前車型全車長時，該短暫提速範圍維持前一低速；遇到更低限制仍取更低值。恰好一個車長保留提速區間。
- 前方雷達、實際超速判定、脫軌門檻與自動時刻計算共用整理後速限。解除限速仍須等車尾通過。
- 工坊表格的「此車型單段基準」顯示該段單獨計算值；駕駛實際限制還會納入彎道組、短暫提速與全車佔用範圍。切換車型會依新車長重算。

### 中間站開始與折返
1. 在駕駛室「模擬起始站」選站，再按「從選取站開始」。列車置於該站停車線，後續時刻依目前難度重算，本次成績歸零。
2. 「反向行駛」可切换順／逆方向；起始站下拉選單會隨方向改變，排除該方向已無下一站的終點。
3. 終點停妥、開門結算後可按「終點折返」。新班次從原終點出發，保留累積成績、超速秒數及急煞次數，停站等候時間計入時鐘，再按 P 發車。
4. 山手線完成一圈後可按「環線下一圈」同向續行，或按「終點折返」換向。這是遊戲班次續行功能，不是對真實山手線折返營運方式的描述。
5. 折返與下一圈都重新計算該班次時刻；原路線 JSON 和工坊站點不會被裁切。中間站起跑保留後方完整軌道。

### 曲線簡化
- 線形最大容許偏差擴大為 1–500 m，可擬合成一段圓弧或兩段相切圓弧。
- 仍保護站點位置、手動限速分界、高度模式分界與不連續高程。固定絕對高程可合併且保留原高程折點；切換坡道／緩坡不合併。
- 套用前可看橘色預覽、線段數及偏差上界；可復原。大偏差可能明顯改變路徑，需由預覽決定是否接受。
- 內附板南線測試：20 m 時整線 335 → 111 段；龍山寺至西門站間 50 m 時可化為 4 段、500 m 時可化為 2 段（這個大範圍設定包含站間直線也一起擬合）。站點平面位置保留。
- 簡化後里程及曲線限速會改變，地形里程同步對應；抵達秒數清空，套用試駕時可自動重算。

# 0.1.5.1 高程編輯更新

在「03／區段幾何與高度」：

- **全部固定為絕對高程**：把地面、高架、地下區段當前的完整高程轉成絕對高程。保留區段內每個地形折點，不增加水平幾何線段；已有絕對高程、切換坡道、緩坡保留形狀並固定起點。之後可重新匯入原始 DTM／地形 CSV，軌道高程不隨地形改變。
- 每列勾選框支援多選、跨頁保留選取、Shift 連續範圍選取；「全選所有區段」涵蓋所有頁面。選擇同步高度模式後按「套用至選取區段」。切換至地面／高架／地下會重新跟隨地形，預設偏移為 0／10／-20 m。
- **統一斜率**：勾選至少兩個相鄰區段，輸入整組起點／末端絕對高程，按確定。依各段累計長度內插，節點高程四捨五入至 0.01 m；因取位，各段斜率可能存在極小差異。首尾值預填目前實際軌道高程。操作後全部選取區段為絕對高程。
- 絕對高程／坡道模式的第一個高度欄為「起點絕對高程」，第二欄為「末端高程」。修改固定高程的端點會清除該段內部固定折點，改成兩端之間的直線坡。未選取區段保持原值，如交界高度不連續，程式會提示補坡道。
- 三種操作皆支援復原／重做；儲存 JSON 可保留固定高程。舊版本不支援新固定高程資料，請使用本版載入。

建議流程：匯入 DTM → 平滑地形 → 全部固定為絕對高程 → 重新匯入原始 DTM → 多選相鄰區段整理坡度。

驗證：76 項 Python 測試、69 項模擬 DOM 操作，以及幾何、高程固定與起點延伸測試通過；尚未在實體 Windows 瀏覽器驗證。

# OpenDenshaGO 0.1.5.1

專案正式名稱：OpenDenshaGO。這是原 Rail GOGO 的延續版本，舊路線 JSON 可匯入。

## 啟動

1. 解壓縮整個 OpenDenshaGO 資料夾，關閉舊版 Python 視窗。
2. 執行 `start_windows.bat`；瀏覽器預設開啟 http://127.0.0.1:8765 。若瀏覽器已有舊頁，按 Ctrl+F5。
3. 如要直接讀 DTM TIFF，先執行一次 `install_dtm_support.bat`。使用 64 位元 Python 3.10 以上；首次安裝需要網路。安裝器建立專案自己的 `.venv` 並安裝 Rasterio，啟動檔會自動使用此環境。
4. 不安裝 DTM 支援也能駕駛、讀路線 JSON／CSV、平滑高程、簡化線段。macOS／Linux 可執行 `python -m pip install -r requirements-dtm.txt`，然後用同一個 Python 執行 `app.py`。

## 直接從 GeoTIFF 取得路線高程

在工坊的「DTM 直接匯入・高程平滑・線段簡化」區域：

1. 先載入或繪製路線。
2. 設定採樣間距（預設 25 m）、高程波段（通常 1）、高程單位（通常公尺），取樣預設雙線性插值。
3. 選取 DTM／DEM `.tif` 或 `.tiff`。檔案只送到本機 Python 程式，沒有傳至外部服務。
4. 程式依路線經緯度轉換到 TIFF 座標系統，讀取沿途地面高度，在海拔斷面圖以橘色虛線預覽。
5. 確認後按「套用預覽結果」。原始採樣點也存入路線 JSON，之後可平滑或還原；可匯出目前 `s,z` CSV。

這是沿路線的高程斷面，不是製作整個區域的平面等高線圖。自動轉換水平座標，不會自動做垂直基準／大地水準面轉換。請確認資料的高程單位和基準。

支援單一有地理定位的 GeoTIFF／BigTIFF，上限 2 GiB；多圖幅先在 QGIS 合併成涵蓋全線的 GeoTIFF，大檔可先裁切。必須涵蓋遊戲路線兩端的緩衝段。沒有 CRS 時才依資料說明填寫覆寫 EPSG。讀取採分塊方式，不會整幅載入記憶體。

缺值、NoData、超出範圍、無法識別定位或無效高程會列出有問題的里程，整次匯入不套用。彩色影像／Terrain RGB 不是本功能的數值高程輸入。双線性插值鄰近格子有缺值時也會拒絕，可改最近像素查明邊界狀況，不能藉此補出沒有的地形。

## 地形高程平滑

- 輸入平滑範圍（5–5000 m，預設 100 m）及強度（50%／100%），按「預覽高程平滑」。
- 按實際距離進行三次移動平均，不會因某處線段較密、採樣點較多而額外加權。
- 顯示處理前後最大坡度與最大高程改動量；橘色虛線顯示候選地面。原地形仍為綠色。
- 路線首尾地面高程固定；保留原始匯入／首次平滑前的高程。可「預覽還原原始高程」後套用，或使用復原／重做。
- 貼地、高架與地下會跟隨處理後地形；絕對高度、坡道與緩坡的設定參數不變，但其起始高程仍依前段末端而定，請檢查銜接。
- 平滑是編修辅助，不保證坡度符合特定鐵路標準，也不會自動把山谷變成橋梁或山體變成隧道。

可先用 100 m 看結果，仍有短距離尖峰時增加範圍；過於抹平真實起伏時降低範圍或強度。這些是遊戲編修起始值，不是實車設計參數。

## 線段簡化

1. 輸入最大容許平面偏差，預設 5 m，按「預覽線段簡化」。
2. 平面圖橘色虛線是候選線形；顯示段數、路線長度變化、偏差上界和站點位置誤差。
3. 套用後，站點與地形里程同步對應新線形；抵達秒數清空，請重新自動排時。

簡化合併相近直線／圓弧，不會把整條線一律改成折線。保護站點、起始站、手動限速和高度模式分界；絕對高度、坡道、緩坡段不合併。站點平面位置需通過 1 mm 以內的檢查才接受。曲線半徑可能變化，因此系統計算限速也可能改變。

基於保護既有設定，曲線密集的路線不一定能大幅減少。若没有安全可減少的結果，會保留原線形。原路線包 5 m 測試例：高鐵台中至南港 803→433 段。原始包不會自動被簡化，需自行預覽套用。

## 建議順序

匯入路線 → 預覽／套用線段簡化 → 匯入 DTM GeoTIFF → 預覽／套用高程平滑 → 以絕對高程／坡道整理軌道 → 自動排時 → 試駕。

高程變更後，既有手動時刻不會被自動覆寫；若要重算，清空抵達秒數後再按自動計算。任何預覽在原路線被另行編輯後會失效，避免覆蓋新修改。
